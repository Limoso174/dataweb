# 出问题怎么办 · 排错手册

> **先记住这句话：几乎没有什么问题是救不回来的。** GitHub 上有完整历史，最差也能回到昨天的版本。
> 所以别慌，别乱改，先看这份文档。

**用法：** 按 `Ctrl + F` 搜你看到的现象（比如 `白屏`、`NaN`、`冲突`）。

---

# 第一部分 · 页面出问题

## 1. 双击 `index.html` 是白屏 / 空白页

**先做这一件事：按 `F12`，点上面的 Console（控制台）标签，看有没有红色文字。**

### 情况 A：Console 有红字

红字第一条就是病根。看它说的文件名和行号，比如 `app.js:42`。

常见红字和含义：

| 红字 | 意思 | 怎么办 |
| --- | --- | --- |
| `Unexpected token` / `Unexpected end of input` | 代码有语法错误，多半是**少了个括号、逗号或引号** | 看你最近改的那几行 |
| `Cannot read properties of undefined (reading 'xxx')` | 有个东西是空的，你却在它身上取东西 | 通常是数据里缺字段，或者变量名写错 |
| `X is not defined` | 用了一个不存在的名字 | 拼写错误，或者忘了加载文件 |
| `Cannot read properties of null` | 页面上找不到那个元素 | `index.html` 里缺了那个 `id` |
| `Failed to load resource` | 文件没找到 | 文件名写错，或不在同一文件夹 |

**修改思路：** 不要整段重写，只改红字指向的那一行附近。改完刷新，看红字变了没有——变了说明你改动生效了，只是还没改完。

### 情况 B：Console 没有红字

那问题不在代码报错，看下面几条。

---

## 2. 页面有内容，但没有样式（黑字白底）

`style.css` 没被读到。检查三件事：

1. **在同一个文件夹吗？** `style.css` 必须和 `index.html` 并排放着。
2. **`index.html` 的 `<head>` 里有这一行吗？**
   ```html
   <link rel="stylesheet" href="style.css">
   ```
3. **文件名真的叫 `style.css` 吗？**
   打开文件资源管理器 → 查看 → 勾选"文件扩展名"。
   如果显示 `style.css.txt`，说明你保存时被记事本加了后缀，重命名去掉 `.txt`。

---

## 3. 页面有标题有样式，但没有数字、没有图

`data.js` 或 `app.js` 没加载，或者报错了。

**检查 1：`index.html` 底部有没有这两行，顺序对不对？**

```html
<script src="data.js"></script>
<script src="app.js"></script>
```

- **顺序不能反**（`app.js` 要用 `data.js` 里的东西）
- 必须在 `</body>` **之前**，也就是页面的最后

**检查 2：** 按 `F12` 看 Console 有没有红字。

**检查 3：** 按 `F12`，点 **Console**，输入下面这行，回车：

```javascript
DATA
```

- 如果输出了一堆数据 → `data.js` 加载正常
- 如果输出 `undefined` → `data.js` 没加载，或者里面有语法错误

---

## 4. 页面上出现 `NaN`、`undefined`、`null`

这三个是"算不出来"的信号，性质不同：

| 看到的 | 意思 | 常见原因 |
| --- | --- | --- |
| `NaN` | Not a Number，"不是数字" | 拿文字做了数学运算，或者 0 做了除数 |
| `undefined` | "这个东西不存在" | 取的字段名写错了，或者那个字段没有值 |
| `null` | "这里明确是空" | 数据里本来就是 `null`，代码没处理 |

### 怎么查

1. 按 `F12` → Console
2. 找到是哪个数字坏了（比如客单价显示 `NaN`）
3. 去看 `data.js` 里对应的计算：

```javascript
aov: orders > 0 ? revenue / orders : null
```

这行的意思是"如果订单数大于 0 才做除法，否则给 null"。**如果没有这个判断，订单数是 0 时会 0/0 = `NaN`。**

**修复原则：任何除法前面都要判断分母是不是 0。**

### 如果是 `undefined`

八成是字段名对不上。`data.js` 里叫 `visits`，`app.js` 里写成了 `visit`。**去两个文件里搜一下，对一对。**

---

## 5. 我改了文件，但页面没变化

**按 `Ctrl + F5`**（强制刷新，会跳过缓存）。

还是没变？检查：

1. 文件**保存了吗**？VS Code 里标签页上有个小圆点，说明没保存。`Ctrl + S`。
2. 你改的是**另一个文件夹里的文件**吗？常见于电脑上有两份项目副本。
3. 浏览器打开的是**本地文件**还是**网上的网址**？改本地文件，网上的网站不会变，要推送后等 1–2 分钟。

---

## 6. 排版乱 / 卡片被撑破 / 有横向滚动条

**原因：** 某个内容比它的容器宽。

**最常见的是超长数字**（比如 `¥99,999,999.00`）。

**怎么查：** 按 `F12`，点左上角的箭头图标（检查元素），把鼠标移到出问题的地方，它会告诉你是什么元素、多宽。

**怎么修：** 在 `style.css` 里给那个容器加：

```css
min-width: 0;           /* 防止被内容撑开 */
overflow-wrap: anywhere; /* 让长内容换行而不是溢出 */
```

我们的 `style.css` 里已经加好了。如果你新加了东西导致溢出，照这个思路加。

---

## 7. 手机上打开是空白 / 字挤在一起

- **字挤在一起**：`index.html` 的 `<head>` 里必须有这一行：
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1">
  ```
- **手机上空白**：可能是浏览器不支持你用的语法。用最新版 Chrome 或 Safari 打开试试。

# 第二部分 · Git / 同步出问题

## 8. 点 Push 报错，说被拒绝了

**原因：** 队友在你之前推了新东西，你本地的版本过时了。**这非常正常，不是出错。**

**怎么办（GitHub Desktop）：**

1. 点上方 **Fetch origin**
2. 出现 **Pull origin** 就点它
3. 拉完之后再点 **Push origin**

**命令行：**

```
git pull
git push
```

如果 `git pull` 时提示冲突，看第 10 条。

---

## 9. 点 Pull 报错，说有本地改动

**原因：** 你有还没提交的改动，Git 不敢直接覆盖。

**怎么办：** 先把你的改动提交掉，再拉。

- **GitHub Desktop**：左下角填说明 → **Commit to main** → 再点 **Pull origin**
- **命令行**：`git add .` → `git commit -m "..."` → `git pull`

---

## 10. 冲突（Conflict）怎么办 ⚠️ 新手最怕这个

### 冲突长什么样

打开文件，会看到这种奇怪的东西：

```
<<<<<<< HEAD
  --primary: #4f6ef7;
=======
  --primary: #ff6b6b;
>>>>>>> 队友的改动
```

意思是：**你写的是蓝色，队友写的是红色，Git 不知道听谁的，停下来问你。**

### 怎么解决（用 VS Code，最简单）

1. 用 VS Code 打开这个文件
2. VS Code 会在冲突处显示几个小按钮（淡淡的字，鼠标移上去才明显）：
   - **Accept Current Change** —— 保留**你的**
   - **Accept Incoming Change** —— 保留**队友的**
   - **Accept Both Changes** —— **两个都留**
   - **Compare Changes** —— 左右对比着看
3. **想清楚要哪个**，点对应的按钮
4. **检查文件里还有没有 `<<<<<<<` 这种符号**（有的话说明还有没处理的）
5. `Ctrl + S` 保存
6. 双击 `index.html`，确认页面是正常的
7. 提交 + 推送

### 不知道怎么选的时候

**别赌。** 发群里问："`style.css` 里配色冲突了，你要蓝色还是红色？"

**或者最简单的判断：这是谁的文件？**

- 冲突在 `style.css` 里 → 听 **C** 的
- 冲突在 `data.js` 里 → 听 **A** 的
- 冲突在 `index.html` 里 → 听 **B** 的
- 冲突在 `app.js` 里 → 听 **D** 的

**冲突永远只该发生在自己的文件里。** 如果你在别人的文件里看到冲突，说明有人违规改了别人的文件——这种情况**一律保留文件主人的版本**，然后问那个人要不要补回自己的改动。

### 更省事的办法

**别手动解决，先看看能不能不冲突：** 如果两个人的改动在文件的不同位置，Git 一般能自动合并，不会报冲突。
报冲突说明改了**同一行**。这通常意味着两个人在做同一件事——**这本身就是个协作问题，值得在站会上说一句。**

---

## 11. 东西被覆盖了 / 队友的改动不见了

**先别做任何操作。** 你的东西大概率还在，只是不在最新版本里。

### 办法一：从历史记录找回来（GitHub Desktop）

1. 打开 GitHub Desktop
2. 点顶部的 **History**（历史）
3. 左边会列出每一次提交，点进去能看到具体改了什么
4. 找到"东西还在"的那一次
5. 右键那次提交 → **Revert changes in commit**（撤销这次提交的改动）
6. 确认后它会把那次提交**反向操作**一遍，把东西还原回来

### 办法二：从 GitHub 网页上复制回来（更直观）

1. 打开仓库页面，点 **commits**（提交数那个数字）
2. 找到之前的某一次提交，点进去
3. 点文件名，看到**那个版本的完整内容**
4. 复制内容，粘回你本地的文件
5. 提交

**这个方法的好处：你能亲眼看到"改坏之前长什么样"，然后一段段挑回来。**

### 办法三：直接问那个人

如果是队友的改动没了，**最快的办法就是问他要一份他电脑上的文件**。
他电脑上有完整的一份，发给你，你粘回去就行。**别为了面子在那找半小时。**

---

## 12. 文件被误删了

**GitHub Desktop：** 如果删除还没提交，左边 **Changes** 里会显示红色的删除项，右键 → **Discard changes**，文件就回来了。

**如果已经提交了删除：** 从 **History** 里找到删除之前的那次提交，进入网页版，把文件下载回来。

# 第三部分 · 终极兜底方案

## 13. 实在搞不定了，怎么办

**这条路 100% 有效，代价是丢掉本地的修改历史。**

### 步骤

**第 1 步：把你自己的成果备份出来**

- 打开你的项目文件夹
- 找到**你负责的那个文件**（比如你管 `style.css`，就只要 `style.css`）
- 复制，粘贴到**桌面**上，改个名：`style-备份.css`

> 只备份你自己的文件。别人的文件从 GitHub 重新拉，不要用你本地的（可能已经坏了）。

**第 2 步：删掉整个项目文件夹**

在 GitHub 网站上先确认：仓库里的版本是**能用的**（打开网页版看看代码对不对）。

如果是，就可以删本地文件夹了。

**第 3 步：重新下载（Clone）**

GitHub Desktop → **File** → **Clone repository** → 选你们的仓库 → 选个位置 → **Clone**

**第 4 步：把你的备份放回去**

把桌面上那个 `style-备份.css` 改名成 `style.css`，放进新下载的文件夹里。

**第 5 步：打开看一眼**

双击 `index.html`。正常就提交 + 推送。

**第 6 步：不正常就再找一个人一起看**

把 `style.css` 先删掉，从别处拉一份能用的，然后**一点点**把你的改动加回去。

---

## 14. 如何避免下次再遇到

按重要性排：

1. **每天上传一次。** 90% 的"东西丢了"，都是因为把一周的工作憋在一个没提交的文件夹里。
2. **只改自己的文件。** 绝大多数冲突和覆盖，都源于这条被破坏。
3. **改完就按 F5。** 不要写两小时再看，出错了你根本不知道是哪一行。
4. **大改之前，先把当前能用的版本提交一次。** 这样改坏了随时能退回来。

---

# 最后

## 遇到问题时的正确顺序

```
① 按 F12 看 Console 有没有红字
② 按 Ctrl+F 在本文档里搜你看到的现象
③ 找到对应条目，按步骤做
④ 30 分钟没解决 → 群里喊人，把红字截图发出来
⑤ 还是不行 → 走第 13 条终极方案
```

**第 4 步是最重要的。** 新手最常见的错误是一个人闷头搞两小时，而队友 5 分钟就能看出来。

**这不丢人，这是效率。**
