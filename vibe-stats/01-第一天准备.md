# 第一天准备 · 四个人的电脑都要配好

> 这一步**最花时间也最容易卡住**。建议在项目开始前一天各自做完，别占用第 1 天开会的时间。
> 遇到卡住的地方，直接跳到本文最后一节「常见问题」，或者发群里让 D 帮你看。

---

## 一、要装什么（先把清单看清）

| 东西 | 是否必须 | 大概耗时 | 用来干嘛 |
| --- | --- | --- | --- |
| Chrome 或 Edge 浏览器 | 必须（一般已有） | 0 | 打开网页、看效果、查报错 |
| VS Code（写代码的软件） | 必须 | 5 分钟 | 编辑那 4 个文件 |
| Git | 必须 | 5 分钟 | 跟队友同步文件 |
| GitHub Desktop | **强烈建议** | 5 分钟 | 用鼠标点点就能同步，不用记命令 |
| GitHub 账号 | 必须 | 3 分钟 | 放项目的地方 |
| Node.js / npm | **不需要** | — | 本项目故意不用 |
| Python / 数据库 / 服务器 | **不需要** | — | 本项目故意不用 |

### 为什么不用装 Node.js？

你可能会搜到"做网页要先装 Node.js"，那是做**大型项目**（用 React、Vue 那种框架）才需要的。

我们这个项目是**最基础的三个东西**：HTML + CSS + JavaScript。浏览器天生就懂，**不需要任何编译、打包、安装**。

好处很实在：

- 少一个装不上的环节（Node 装不上是新手第一大坑）
- 少一类报错（`npm install` 失败、版本冲突、端口占用……）
- 双击就能看，不用记"先运行什么命令再打开"
- 四个人交上来的文件，拿到谁的电脑上都能直接打开

> 如果后面你们想升级成 React，再装也不迟。**先用最简单的方式把东西做出来**，这是新手最该守的纪律。

## 二、第 1 步：装 VS Code

VS Code 是微软出的免费代码编辑器。它不是必须的（记事本也能改），但**没有它你会痛苦十倍**：它会给代码上色、提示错误、显示行号。

**怎么做：**

1. 打开 https://code.visualstudio.com/
2. 点蓝色大按钮 **Download for Windows**（如果是 Mac，会自动给你 Mac 版）
3. 下载完双击运行
4. 安装时**勾选**这几项（很重要）：
   - ☑ 将"通过 Code 打开"操作添加到 Windows 资源管理器文件上下文菜单
   - ☑ 将"通过 Code 打开"操作添加到 Windows 资源管理器目录上下文菜单
   - ☑ 添加到 PATH
5. 一路"下一步"装完

**装完后验证：**

右键点任意一个文件夹 → 菜单里应该有 **「通过 Code 打开」**。
有这一项，说明装对了。

**建议装两个插件**（打开 VS Code，左边点方块图标，搜名字，点 Install）：

| 插件名 | 作用 |
| --- | --- |
| **Chinese (Simplified)** | 把 VS Code 界面变成中文 |
| **Live Server** | 改完代码自动刷新页面，不用一直按 F5 |

> Live Server 用法：打开 `index.html`，右下角点 **Go Live**，会打开一个 `localhost:5500` 的页面。
> 之后你保存文件，页面**自动刷新**。这个小工具能省掉你几百次按 F5。

## 三、第 2 步：装 Git

Git 是记录版本、跟队友同步的工具。

**怎么做（Windows）：**

1. 打开 https://git-scm.com/download/win
2. 下载会**自动开始**（文件叫 `Git-2.xx.x-64-bit.exe`）
3. 双击运行，**所有选项都用默认，一路点 Next**（有 10 来个页面，不用看，直接下一步）
4. 装完

**装完后验证：**

按 `Win + R`，输入 `cmd`，回车，打开黑色命令行窗口。输入：

```
git --version
```

回车。**应该显示类似 `git version 2.43.0.windows.1`。**

- 显示了 → 成功
- 显示"不是内部或外部命令" → 看本文最后「常见问题」第 1 条

> ⚠️ **装完 Git 后，一定要关掉所有已打开的命令行窗口再重新开**，否则它找不到新装的 Git。

## 四、第 3 步：注册 GitHub

1. 打开 https://github.com/
2. 点右上角 **Sign up**
3. 填邮箱、密码、用户名（用户名用英文，会成为你们网址的一部分，别用乱码）
4. 去邮箱点验证链接
5. 登录后，跳过所有"选择你的兴趣"之类的引导页

> **免费版完全够用。** 不需要升级付费。

---

## 五、第 4 步：告诉 Git 你是谁

每台电脑**只做一次**。这样你提交的改动才会标上你的名字。

打开命令行（`Win + R` → `cmd` → 回车），**逐行**输入下面两行，每行按回车：

```
git config --global user.name "你的名字"
git config --global user.email "你注册GitHub用的邮箱"
```

比如：

```
git config --global user.name "张三"
git config --global user.email "zhangsan@example.com"
```

**没有输出就是成功。**（Git 的风格是"没消息就是好消息"）

**检查一下：**

```
git config --global --list
```

应该能看到你刚填的 `user.name` 和 `user.email`。

## 六、第 5 步：建一个仓库（只由 D 做一次，其他人跳过）

**只有一个人（D）做这一步，做完把网址发群里。**

1. 登录 GitHub，右上角 **+** → **New repository**
2. **Repository name** 填 `stat-web`（英文，不要空格）
3. 选 **Public**（公开；免费版私有仓库不能用 Pages 托管网页）
4. **勾选** ☑ **Add a README file**
5. 点绿色 **Create repository**

**建好后，把 `起步模板/` 里的 4 个文件传上去：**

1. 在仓库页面点 **Add file** → **Upload files**
2. 把 `index.html`、`style.css`、`data.js`、`app.js` 四个文件**一起**拖进去
3. 下面的说明框写一句"初始版本"
4. 点绿色 **Commit changes**

**然后开启网站托管（这样你们很早就有一个能打开的网址）：**

1. 仓库页面点 **Settings**（顶部那排）
2. 左边菜单找 **Pages**
3. **Source** 选 **Deploy from a branch**
4. **Branch** 选 **main**，文件夹选 **/ (root)**，点 **Save**
5. 等 1–2 分钟，页面顶部会出现一行：**Your site is live at `https://你的用户名.github.io/stat-web/`**

**把这个网址复制到群里。** 现在它是一个真实的、任何人都能打开的网页了。

> ⚠️ 注意：仓库根目录必须有 `index.html`，这是网站默认打开的文件。名字不能改。

## 七、第 6 步：把仓库下载到自己电脑（A、B、C 都要做）

有两种方式，**四人统一用同一种**，别混着来。

### 方式一：GitHub Desktop（推荐给新手）

纯鼠标操作，不用记命令，不用搞密码。

1. 打开 https://desktop.github.com/ ，下载安装
2. 打开后点 **Sign in to GitHub.com**，用你们的账号登录
3. 点 **File → Clone repository**
4. 在列表里选 `你们组/stat-web`，**Local path** 选一个你记得住的位置（比如 `D:\项目`）
5. 点 **Clone**

搞定。以后**所有操作都在这个软件里**：

| 你想干什么 | 点哪里 |
| --- | --- |
| 拿到队友的新改动 | 上方 **Fetch origin** 按钮（有时显示 **Pull origin**） |
| 看看自己改了什么 | 左边 **Changes** 列表 |
| 上传自己的改动 | 左下角填一句说明 → **Commit to main** → 上方 **Push origin** |

**这个软件你每天只需要记两个按钮：上面拉（Pull），下面传（Push）。**

### 方式二：命令行（D 用这个更稳，其他人可以跳过）

打开命令行，进到你放项目的文件夹，然后：

```
git clone https://github.com/你的用户名/stat-web.git
```

它会在当前文件夹里建一个 `stat-web` 文件夹，里面就是那 4 个文件。

> 第一次用命令行推送时，GitHub 会要密码。**现在不能用账号密码了**，要用"令牌（Token）"。
> 这就是为什么推荐新手直接用 GitHub Desktop——它帮你处理了这件事。

## 八、第 7 步：确认你也能改、也能传

**这步必须每个人都亲自做一遍**，别等第 3 天才发现传不上去。

1. 用 VS Code 打开你下载下来的 `stat-web` 文件夹（右键文件夹 → 通过 Code 打开）
2. 打开 `index.html`
3. 找到 `<h1>运营数据概览</h1>`，把「运营数据概览」改成「运营数据概览 · 张三测试」
4. 保存（`Ctrl + S`）
5. 双击 `index.html`，确认浏览器里标题变了
6. 用 GitHub Desktop（或命令行）**提交 + 推送**
7. 去 GitHub 网站上刷一下，看到你的改动 → **成功**
8. **改回去，再提交一次**（别把测试字样留在页面上）

**然后群发一句"我传上去了"，让其他三个人点一下 Pull，确认能看到你的改动。**

四个人都走完这一圈，第 1 天的准备工作才算真的完成。

## 九、常见问题

### 1. 输入 `git --version` 显示"不是内部或外部命令"

原因：Git 装了，但命令行没找到它。

- **先关掉所有命令行窗口，重新开一个再试**（最常见的原因）
- 还不行：重新运行 Git 安装包，在 **"Adjusting your PATH environment"** 那一页，选 **Git from the command line and also from 3rd-party software**（默认就是这个，可能之前选错了）
- 或者干脆用 GitHub Desktop，不需要命令行

### 2. 双击 `index.html` 打开是空白页

- 右键 → **打开方式** → 选 **Chrome** 或 **Edge**（可能被记事本关联了）
- 还白屏：按 `F12` 看 Console 有没有红字，然后看 [`06-出问题怎么办.md`](06-出问题怎么办.md)

### 3. 打开后页面没有样式（只有黑字白底）

说明 `style.css` 没被读到。检查三件事：

- `style.css` 和 `index.html` 在**同一个文件夹**里
- `index.html` 里有 `<link rel="stylesheet" href="style.css">` 这一行
- 文件名没有写成 `styles.css` 或 `style.css.txt`（打开"显示文件扩展名"检查）

### 4. 打开后没有数字和图表

说明 `app.js` 或 `data.js` 出错或没加载。按 `F12` → Console，看红字。
也检查 `index.html` 底部有没有这两行、顺序对不对：

```html
<script src="data.js"></script>
<script src="app.js"></script>
```

**顺序不能反**：`app.js` 要用 `data.js` 里的东西。

### 5. GitHub Desktop 里点 Push 报错

- 先点 **Fetch origin**，如果有 **Pull origin** 就点它，把队友的改动拉下来
- 拉完再推送
- 还报错，把红字截图发群里

### 6. 我不知道该把我的文件放在哪

统一放在 `stat-web` 文件夹里，**和 `index.html` 同一层**。
不要建子文件夹，不要改名。四个文件就这样并排放着。

### 7. 我的改动好像把队友的东西弄没了

**先别慌，别继续改。** GitHub 上还留着历史版本，能找回来。
看 [`06-出问题怎么办.md`](06-出问题怎么办.md) 的「东西丢了/被覆盖了」那一节。
