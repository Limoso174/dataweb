# 四人小组 · 做一个数据统计网页 · 新手版

> **这份文档是总目录。先读这里，再按天往下走。**
> 不需要你会编程，文档里每一步都写了"点哪里、打什么、出错了看哪个文件"。

---

## 一、先把话说清楚：我们要做的事有多简单

我们要做的，是**一个网页，打开就能看到几个数字和一张图**。

整个项目只有 **4 个文件**：

```
我们的项目/
  index.html   ← 页面上有哪些东西（标题、卡片、图、表格）
  style.css    ← 这些东西长什么样（颜色、大小、间距）
  data.js      ← 数字从哪来、怎么算出来的
  app.js       ← 怎么把数字摆到页面上、点了按钮怎么变
```

就这样。**没有后端、没有数据库、不用装开发工具、不用打包。**

- 想改页面结构 → 打开 `index.html`
- 想改颜色样子 → 打开 `style.css`
- 想改数字和算法 → 打开 `data.js`
- 想改图表和交互 → 打开 `app.js`

### 怎么看到效果

**双击 `index.html`**，用 Chrome 或 Edge 打开，就看到了。改完文件保存，按 `F5` 刷新，就能看到改动。

> 这一步现在就能试：去打开 `起步模板/index.html`。看到页面，说明你的电脑什么都不用装。

## 二、开始之前，四个人的心理准备

做这类小组项目，翻车从来不是因为"不会写代码"，而是因为下面这几件事。先记住，能省下好几天：

**1. 一个人管一个文件，别乱动别人的。**

四个人同时改同一个文件，一定会互相覆盖，而且新手救不回来。
所以我们把项目切成 4 个文件，一人一个。**你要改的东西如果不在你的文件里，找那个人说，不要自己动手。**

**2. 每天结束前，页面必须是能打开的。**

不管做到哪一步，下班前双击 `index.html` 必须是好的。
做了一半的功能，就把入口先藏起来，别让整个页面白屏。

**3. 每天必须把你的成果传上去。**

不要憋到第 6 天一次性提交。憋着的代码等于不存在，而且会跟别人的冲突。
**每天至少上传一次**，哪怕做得很少。

**4. 卡住超过 30 分钟就喊人。**

新手最常干的事是一个人卡两小时不敢说。30 分钟没进展，就在群里发一句"我卡在 XXX 了"。
这不会显得你弱，这会救整个项目。

## 三、四个人分别管什么

先看这张表，**第 1 天开会时把它填上名字**。

| 代号 | 管哪个文件 | 具体做什么 | 需要会什么 |
| --- | --- | --- | --- |
| **A · 数据** | `data.js` | 找数据、整理数据、定字段、定指标怎么算 | 会用 Excel 就够了 |
| **B · 页面** | `index.html` | 页面上有哪些区块、每个区块放什么、文案 | 细心、有条理 |
| **C · 样式** | `style.css` | 颜色、字号、间距、手机上好不好看 | 有审美感即可 |
| **D · 交互和发布** | `app.js` | 画图、筛选器、加载/出错/没数据三种状态、最后上线 | 四个里最"技术"的 |

四条补充：

1. **D 的活最难，其他人做完自己的要去帮 D。** 尤其第 5 天。
2. **B 和 C 可以合并成一个人**（如果只有三个人）。页面结构和样式本来就近。
3. **A 的活最容易，但千万别小看。** A 定错了字段，四个人全白干。
4. **不是永远固定。** 第 5 天谁闲谁帮别人，但**文件归属不变**——帮忙也要通过那个人。

> 如果你们四个人里有一个明显更会电脑的，让他做 D，但**其他人不能因此不管自己的文件**。

## 四、六天怎么走

下面每天都有：**今天的目标**、**每个人干什么**、**今天结束前必须验收什么**。

时间只是参考，你们可以压缩或拉长，但**顺序不要改**。

---

### 第 1 天 · 把话说清楚，让项目跑起来

**目标**：四个人电脑上都能打开同一个页面，并且知道要做什么。

**上午（2 小时，四个人必须同时在线，不要各干各的）：**

一起把 [`一页纸规格.md`](一页纸规格.md) 填完。这份文件只有一页，回答四个问题：

1. 这个页面给谁看？他看完要做什么决定？
2. 页面上要有哪 3–5 个数字？（**最多 5 个，多一个都不行**）
3. 每个数字怎么算出来的？（写到"能照着实现"的程度）
4. 这次**明确不做什么**？

> ⚠️ 第 3 个问题最容易糊弄过去。写不出"怎么算"，就说明这个指标你们还没想清楚，先砍掉。
> 反例：「活跃用户数」。正例：「活跃用户数 = 当天有 ≥1 次访问的去重用户」。
> 详细说明看 [`03-数据怎么定.md`](03-数据怎么定.md)。

**下午（分头干）：**

| 谁 | 做什么 |
| --- | --- |
| **A** | 把真实数据整理成 `data.js` 的格式（用 Excel 拼，方法在 `03-数据怎么定.md`） |
| **B** | 在纸上画出页面长什么样：从上到下有哪些区块 |
| **C** | 找 2–3 个"看起来舒服"的同类网站，截图发群里，定一个配色方向 |
| **D** | 建 GitHub 仓库，把 `起步模板/` 里 4 个文件传上去，并让 A/B/C 都能下载下来 |

四个人各自的电脑准备（装软件、建账号），看 [`01-第一天准备.md`](01-第一天准备.md)。**这一步最花时间，建议第 1 天上午之前各自先做完。**

**今天结束前必须验收：**

- [ ] `一页纸规格.md` 填完，四个人都看过、都同意
- [ ] 四个人的电脑上，双击 `index.html` 都能看到同一个页面
- [ ] 每个人都知道自己管哪个文件
- [ ] GitHub 仓库建好了，四个人都有权限

---

### 第 2 天 · 先让"一条数据"从头跑到尾

**目标**：把**最简单的一个数字**，从数据一路做到页面上显示出来。

这一天**只由 A 和 D 两个人主写**，B 和 C 不要开新东西。听起来浪费，其实是最省时间的做法，原因见下。

**A 干什么：**

- 用真实数据替换 `data.js` 里的假数据（先只做**一个指标**，不要贪多）
- 确保这个数字算出来是对的——拿 Excel 手算一遍对一下

**D 干什么：**

- 把 `app.js` 里的 5 张卡片先删到只留 1 张，专门显示 A 给的这一个指标
- 确认页面上那个数字跟 A 在 Excel 里算的一样

**B 干什么（不写代码）：**

- 把页面结构架子搭好：标题区、筛选区、卡片区、图表区、表格区
- **每个区先留空容器**（`index.html` 里已经有示例），以后别人往里填就不用动这个文件了
- 写页面上的所有文字（标题、说明、口径脚注）

**C 干什么（不写代码）：**

- 把 `style.css` 里的配色改成你们定的方案
- 调字体大小、间距
- **准备一份"脏数据清单"**：真实数据里可能有哪些坑（缺失、格式乱、异常大值）

**为什么这一天不能四个人一起写？**

因为后面三个人做的事，都需要一个"照着抄的样例"。
第 2 天做出的这**一条**完整链路，就是那个样例。之后 A 加第二个指标、D 加第二张图，都可以照着第一个的样子做，出错率会低很多。

四个人第一天就并行，做出来的是四个风格不同、互相对不上的半成品，第 4 天合的时候会崩。

**今天结束前必须验收：**

- [ ] 真实数据的一条指标，在页面上显示出来了
- [ ] 这个数字跟 Excel 手算的一致
- [ ] 页面不白屏，双击能打开

---

### 第 3 天 · 分头做，一人一个文件

**目标**：四个人同时推进，互不干扰。

从今天开始，**只改自己那个文件**。

| 谁 | 今天的任务 | 自检 |
| --- | --- | --- |
| **A** | 把剩下 2–4 个指标全部算对 | 每个数字都用 Excel 对过 |
| **B** | 补齐所有区块的容器和文案 | 页面上没有空白区域、没有"TODO"字样 |
| **C** | 样式铺到全站（卡片、表格、筛选条、手机宽度） | 窗口拉窄到手机宽度，没有横向滚动条 |
| **D** | 画趋势图 + 接通筛选器 | 换时间范围/渠道，数字会变 |

**今天的规矩：**

- 每改完一小块，就 F5 看一眼。**不要写一小时再看**，出错时你不知道是哪一行坏的。
- 每完成一块就上传一次（怎么做见 [`02-分工和每天配合.md`](02-分工和每天配合.md)）。
- 页面上有任何看不懂的地方，**先问 B**（结构问题）或 **C**（样式问题）。

**今天结束前必须验收：**

- [ ] 四张/五张卡片都有真实数字
- [ ] 趋势图能画出来
- [ ] 筛选器能用
- [ ] 手机宽度能看
- [ ] 页面没有白屏、没有明显的错位

---

### 第 4 天 · 继续做，同时开始补"不完美的情况"

**目标**：功能齐了，开始补那些"正常情况以外"的东西。

这一天大多数人会觉得"功能都做完了，没事干了"。**其实真正的工作现在才开始。**

| 谁 | 今天的任务 |
| --- | --- |
| **A** | 检查脏数据：空数据、缺字段、超大数字，算出来会不会变成 `NaN` 或 `undefined` |
| **B** | 补文案：指标口径说明、数据来源、更新时间；检查手机上文字有没有挤在一起 |
| **C** | 补"加载中 / 出错 / 没数据"三种状态的样式；检查极端值不撑破布局 |
| **D** | 接好三种状态；加"重试"按钮；检查控制台有没有红色报错 |

**为什么这三种状态这么重要：**

新手做的页面，永远只处理了"数据正常、有 100 条"这一种情况。
但真实情况是：网络会断、数据会空、某个字段会缺。**这三种情况任一发生，页面就会白屏或者显示 `NaN`。**

评委/老师/老板第一件事就是试这些。见 [`03-数据怎么定.md`](03-数据怎么定.md) 里的"五种脏数据"。

**今天结束前必须验收：**

- [ ] 数据全部为空时，页面显示"暂无数据"，不白屏
- [ ] 网络出错时，页面显示"加载失败"，有重试按钮能点
- [ ] 有缺失字段时，页面上没有 `NaN`、`undefined`、`null` 字样
- [ ] 浏览器按 F12 打开控制台，没有红色报错

---

### 第 5 天 · 合起来，磨细节

**目标**：从"能用"变成"敢给人看"。

四个人今天**都在同一个页面上一起看**（可以投屏，一个人操作）。

**按这个顺序过一遍，发现问题当场记下来，分给对应的人：**

1. **从上到下看一遍**：标题 → 来源和时间 → 筛选 → 卡片 → 图 → 表 → 口径
2. **每个数字问一遍**："这个数怎么算的？"答不上来就补口径说明
3. **随便点**：换时间范围、换渠道、快速来回切，看会不会卡住或显示错
4. **把窗口拉窄**到手机宽度，看会不会横向滚动
5. **清空数据**看空状态，**断网**看错误状态
6. **数字格式**：千分位、百分比小数位、金额单位，全站统一
7. **删掉所有调试痕迹**：`console.log`、注释掉的代码、"测试"字样

**今天的重点不是加功能，是减问题。** 想加的新功能一律记下来，做完这版再说。

**今天结束前必须验收：**

- [ ] 上面 7 条全部过完
- [ ] 四个人都亲手点过一遍
- [ ] 页面上找不到明显的错别字和格式不统一

---

### 第 6 天 · 上线，准备演示

**目标**：有一个网址能发给别人，有 3 分钟能讲完的话。

**上午 · 上线**（D 主导，其他人看着学）

用一个叫 GitHub Pages 的免费功能，把网页变成一个网址。步骤在 [`05-上线和演示.md`](05-上线和演示.md)。

**下午 · 准备演示**

演示只需要三句话的结构：

1. **一句话说痛点**："以前要看这些数，得手动打开四个表格加一遍。"
2. **演示三个数字**：不要五个都讲，讲最有说服力的三个。
3. **一句话说结论**："所以我们现在知道 XXX，建议 XXX。"

**必须做的两件保险：**

- **录一段屏**。现场网络挂了、电脑卡了，放录屏。这不是偷懒，是专业。
- **把网址写在一个地方**（手机备忘录），演示时直接打开，不要现场找。

**今天结束前必须验收：**

- [ ] 网址能打开，手机上也能打开
- [ ] 把网址发给一个**没参与项目的人**，他能看懂页面在说什么
- [ ] 录屏文件存在本地，能播放
- [ ] 三个人以上都试讲过一次

## 五、每天固定要做的事（贴在墙上）

不管进行到第几天，每天都是这个节奏：

```
开始工作前           先点"获取最新版本"，把别人的改动拉下来
                     （不做这一步，晚上上传时会打架）

写完一小块           按 F5 看一眼；能看就上传一次

离开之前             上传今天的改动，并在群里说一句"我传了什么"
```

具体的点击和命令，看 [`02-分工和每天配合.md`](02-分工和每天配合.md)。

**每周轮一个人当"合并负责人"**（建议 D 先当第一周），他额外负责：每天晚上确认页面能打开、周五整理一下大家的改动。

## 六、什么时候算"做完了"

最后交之前，对着这张表一条条打勾。**有一条没打勾就不要交。**

- [ ] 双击 `index.html` 能打开，不白屏
- [ ] 每个数字都能说出怎么算的（页面上有口径说明）
- [ ] 页面上有数据来源和更新时间
- [ ] 数据为空时显示"暂无数据"，不白屏、不显示 `NaN`
- [ ] 出错时有提示和重试按钮
- [ ] 手机宽度（窗口拉到最窄）不横向滚动
- [ ] 超大数字不会撑破卡片
- [ ] 按 F12，控制台没有红色报错
- [ ] 四个人都从 GitHub 下载最新版本，双击都能正常打开
- [ ] 网址能发给别人打开
