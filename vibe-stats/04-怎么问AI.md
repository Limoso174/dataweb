# 怎么让 AI 帮忙 · 四个人统一用法

> 我们这个项目里，AI 能帮你写出 70% 的代码。
> 但**剩下 30% 是决定成败的部分**，而且 AI 会用很自信的语气把你带偏。

---

## 一、先认清：AI 能干什么，不能干什么

| AI 很擅长 | AI 会坑你 |
| --- | --- |
| 写一段画图的代码 | **编造不存在的字段名** |
| 解释报错是什么意思 | **编造不存在的函数** |
| 把一段代码改得短一点 | **偷偷引入一个你们没装的库** |
| 写测试数据 | **把你已有的代码改坏** |
| 按你说的格式排版 | **忘记处理空数据** |

### 最重要的一条认知

> ## AI 看不到你的电脑，也看不到你的项目文件夹。

它不知道你们的字段叫 `visits` 还是 `pageViews`，不知道 `index.html` 里有什么，不知道 `style.css` 用了什么颜色。

**你不告诉它，它就会猜。猜出来的东西看起来很像对的，但跟你的项目对不上。**

而且它的语气永远很确定——不会说"我不太确定"。所以你必须自己验证。

---

## 二、四行提问模板

**每次问 AI，都按这四行写。** 少一行，结果质量就掉一截。

```
目标：<一句话，说清要做什么>
相关文件：<把文件内容整个贴进去>
约束：<不许做什么、必须用什么>
验收：<怎么算做完了>
```

### 四行分别在解决什么

| 这行 | 解决什么问题 | 不写会怎样 |
| --- | --- | --- |
| **目标** | 让 AI 知道要做啥 | 它自己发挥，做出一堆你不要的东西 |
| **相关文件** | 补上它看不到的上下文 | 它编字段名，代码粘上去就报错 |
| **约束** | 拦住它"顺手优化" | 它把你别的代码也改了 |
| **验收** | 你自己知道做完没有 | 你觉得"好像对了"，其实是错的 |

### "相关文件"怎么给

复制整个文件内容，粘在提问里。**不要只说"我的 data.js"，它看不到。**

文件不长（我们这个项目每个文件就一两百行），整个贴进去完全可以。

> **通用规则：你让它改哪个文件，就把那个文件的全文贴给它；如果它要用到别的文件里的东西（比如 `app.js` 要用 `data.js` 里的 `DataLib`），把相关的那一段也贴。**

## 三、三个完整例子

### 例子 1：加一张指标卡

**❌ 坏提问：**

> 帮我加一个指标卡

会发生什么：AI 不知道你有哪些数据、卡片长什么样、该加在哪里。它自己编一个 `visitCount`，还自己写了一套样式，跟你的卡片长得不一样。

**✅ 好提问：**

```
目标：在指标卡区域加一张"人均访问次数"卡片，显示 访问量 ÷ 天数

相关文件：
【app.js 的 renderCards 函数】
function renderCards(m) {
  return [
    card('总访问量', formatInt(m.visits), '筛选范围内，所有完整记录的访问数相加'),
    card('订单数',   formatInt(m.orders), '筛选范围内，所有完整记录的订单数相加')
  ].join('');
}
【data.js 的 computeMetrics 返回值】
{ visits, orders, revenue, conversion, aov, byDate: [{date, visits}] }

约束：
· 只改 app.js，不要动 index.html、style.css、data.js
· 必须复用已有的 card() 和 formatInt()，不要新写样式
· 除法要注意天数为 0 的情况，不能出现 NaN
· 不要引入任何新的库

验收：卡片区多出一张"人均访问次数"，跟其他卡片样式一致；
把数据清空后，这张卡显示"—"而不是 NaN。
```

### 例子 2：修一个数字算错的 bug

**❌ 坏提问：**

> 转化率算错了，帮我修

会发生什么：AI 看不到代码，只能瞎猜，可能给你一个完全不相干的改法，甚至把对的改错。

**✅ 好提问：**

```
目标：修 bug。转化率显示成了 391.00%，应该显示 3.91%

现象：orders=570, visits=14560，570/14560 = 0.03915
      页面上显示 "391.00%"，应该是 "3.91%"

相关文件：
【app.js】
function formatPercent(n) {
  if (n === null || n === undefined) return '—';
  return (n * 100).toFixed(2) + '%';
}
【data.js】
conversion: visits > 0 ? orders / visits : null,

约束：
· 只改一处，不要两边都改（否则会变成 0.039%）
· 不要动 data.js 里的计算方式
· 其他用 formatPercent 的地方不能被改坏

验收：页面显示 3.91%；数据为空时仍显示"—"。
```

> 这个例子说明一件事：**报 bug 时给出具体数字和期望结果**，AI 才能定位。
> 只说"算错了"，AI 只能猜。

### 例子 3：改样式

**❌ 坏提问：**

> 这个页面不好看，帮我美化一下

会发生什么：AI 会把整站配色换掉，包括别人已经调好的部分。而且它不知道你们定的配色方案。

**✅ 好提问：**

```
目标：把指标卡的数值字号从 24px 调到 28px，副标题改成更浅的灰

相关文件：
【style.css 的相关部分】
:root {
  --ink:     #0f172a;
  --muted:   #64748b;
}
.value {
  font-size: 24px;
  font-weight: 600;
  letter-spacing: -0.4px;
  font-variant-numeric: tabular-nums;
  overflow-wrap: anywhere;
}

约束：
· 只改 .value 这一个选择器
· 颜色只能用 --muted，不要新增色号
· 不要动布局（grid 那些）
· 超长数字（¥99,999,999.00）不能撑破卡片

验收：卡片数值变大、副标题变浅；把数据里某条 revenue 改成 99999999，
卡片仍然不溢出、不换行错乱。
```

## 四、AI 最常犯的五个错，以及怎么防

### 错 1：编造字段名

它写 `data.pageViews`，但你的是 `visits`。

**防：** 把 `data.js` 里 `window.DATA` 那一段完整贴给它，并加一句"字段名必须用我给的这些，不要自己起名字"。

### 错 2：偷偷引入新的库 ⚠️ 最危险

它会说"先运行 `npm install chart.js`"，或者给你一段 `<script src="https://cdn.../chart.js">`。

**为什么危险：** 我们这个项目故意不用任何库。引入一个库，就引入了一堆装不上、加载失败、版本对不上的问题——而且可能整个页面就打不开了。

**防：** 每次提问都加一句 **"不要引入任何新的库或外部链接，只用我文件里已有的东西"**。

**如果它坚持要加：** 回它一句"不行，请用纯 JavaScript 和手写 SVG 实现"。它做得到——我们的柱状图就是手写的，三十几行。

### 错 3：忘记处理空数据

它写的代码，只要 `records` 是空数组就报错。

**防：** 验收标准里永远加一句"数据为空时不能报错，要显示'暂无数据'"。

### 错 4：顺手改了别的代码

你说"改这个函数"，它把整个文件重写了一遍，顺便把别人的逻辑也改了。

**防：**
- 约束里写清"只改 XXX，其他一律不动"
- **拿到代码后，对比一下：除了它说的地方，别处有没有变？**
- 用 VS Code 的"比较"功能，或者直接把改前的文件备份一份

### 错 5：改别人的文件

你让它改页面结构，它去动 `app.js`。

**防：** 约束里写"只改 `index.html`"，并且**粘代码时只粘那一个文件**。它看不到别的文件，就不会去改。

## 五、拿到 AI 的答案之后，必须做的三件事

**1. 看它改了哪里，不要无脑全选粘贴。**

它可能"顺便"删了你一段代码。扫一眼，确认除了目标位置，别处没变。

**2. 保存，按 F5，亲眼看效果。**

AI 说"这样就完成了"，不代表它真的完成了。**你必须自己看到数字变了。**

**3. 按 F12 看 Console。**

有红字就是有问题，哪怕页面看起来正常。
有时页面看起来是对的，但控制台一直在报错，说明某条路径根本没走通。

> **AI 说"完成"≠ 真的完成。这三步是你唯一的质量保证。**

## 六、AI 给的代码报错了，怎么办

**不要自己瞎改。** 新手瞎改会把能跑的东西改崩。

按这个顺序：

1. 按 `F12` → **Console** 标签
2. 把**红字完整复制**下来（包括文件名和行号，比如 `app.js:42`）
3. 回到和 AI 的对话，发：

```
报错了。

错误信息：
Uncaught TypeError: Cannot read properties of undefined (reading 'visits')
    at renderCards (app.js:42)

完整代码（出错的函数）：
（贴那个函数）
```

**关键：把红字原样贴给它，不要自己总结成"它说有个错"。** 那句英文里包含了文件名、行号、出错类型，这些信息对定位最重要。

### 如果同一个问题问了三轮还没解决

**开一个新对话。** 见下一条。

---

## 七、什么时候该开新对话

| 该开新对话 | 该继续当前对话 |
| --- | --- |
| **AI 开始重复犯同一个错** | 在修同一个 bug 的第 2 步 |
| 换了一个完全不同的功能 | 在同一个文件里连续调整 |
| 对话已经超过 20 轮还在绕 | 需要它记住前面定的约束 |
| 你换了文件在改 | — |

**为什么：** 对话越长，AI 越容易记混前面定的规则，然后开始自相矛盾。新对话 + 重新贴一次文件，往往一下就解决了。

**换功能就换对话，这是经验。**

---

## 八、绝对不能让 AI 碰的东西

| 东西 | 为什么 |
| --- | --- |
| `data.js` 里的字段名和结构 | 改了全组对不上 |
| 别人的文件 | 会冲突，而且你不知道改坏了什么 |
| 任何 `npm install` / `package.json` | 我们不用这些 |
| 任何 `https://cdn...` 的外部脚本 | 断网就白屏，而且不知道加载的是啥 |

---

## 九、AI 用得好的人，和不用的区别

不是"谁会让 AI 写代码"，而是：

- **谁知道要什么**（目标写得清楚）
- **谁给的上下文准**（文件贴全了）
- **谁验证得认真**（每次都按 F5 看 F12）

AI 写得快，但它不知道你们要什么。**想清楚要什么，是四个人的活，不是 AI 的活。**
