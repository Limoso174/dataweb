# 上线和演示 · 第 6 天

> 上线 = 把你的网页放到网上，让别人能用一个网址打开。
> 我们不用买服务器、不用备案、不花钱。

---

## 一、上线是什么，为什么这么简单

你们的 4 个文件本身就是完整的网站。它是**静态**的——没有后端、没有数据库，浏览器拿到文件就能显示。

所以托管这种网站非常便宜甚至免费，GitHub 就白送一个叫 **GitHub Pages** 的功能。

**好处：它是跟仓库连着的。** 你们改了代码推到 GitHub，网站过一两分钟自动更新。不用手动上传。

---

## 二、开启 GitHub Pages（D 做一次，5 分钟）

### 前提检查（很重要）

- [ ] 仓库是 **Public**（公开）。免费账号的私有仓库不能用 Pages
- [ ] `index.html` 在**仓库最外层**，不在任何子文件夹里
- [ ] 4 个文件名全是**小写英文**：`index.html`、`style.css`、`data.js`、`app.js`（GitHub Pages 区分大小写，`Index.html` 会导致 404）

### 步骤

1. 打开你的仓库页面，点顶部 **Settings**（齿轮图标）
2. **左侧**菜单往下滚，找到 **Pages**（在 "Code and automation" 那一组里）
3. **Source** 那一栏，选 **Deploy from a branch**
4. 下面出现 **Branch**：
   - 左边下拉选 **main**
   - 右边下拉选 **/ (root)**
   - 点 **Save**
5. 页面顶部出现一行蓝底提示：**Your site is live at `https://你的用户名.github.io/stat-web/`**
6. **等 1–2 分钟**，然后点那个网址

**打开了、看到页面了 → 上线成功。**

把这个网址发到群里，让四个人都打开确认。

### 如果打开是 404

按顺序检查：

1. **等够时间了吗？** 第一次部署要 1–3 分钟。刷新几下。
2. **文件名对吗？** 必须是 `index.html`，不能是 `Index.html`、`index.htm`、`首页.html`。
3. **在根目录吗？** 如果在 `src/index.html`，那网址要变，最省事的办法是把它挪到最外层。
4. 回 Settings → Pages，看最上面有没有报错信息。

### 如果页面打开但没样式、没数字

说明 `style.css`、`app.js` 没加载成功。检查：

- 文件名大小写是否完全一致（GitHub 服务器区分大小写，Windows 不区分——**这是最容易踩的坑**）
- `index.html` 里引用的路径是 `style.css` 而不是 `./css/style.css`

### 更新网站

改了代码 → 提交 → 推送 → **等 1–2 分钟**。

打开网址如果没变化，按 **`Ctrl + F5`** 强制刷新（浏览器缓存了旧版本）。

## 三、备选方案：Netlify 拖拽上传（不用 GitHub 也能上）

如果 GitHub Pages 搞不定，用这个，**30 秒**：

1. 打开 https://app.netlify.com/drop
2. 把你们那个**装着 4 个文件的文件夹**整个拖进页面上的方框
3. 等几秒，得到一个网址

**缺点**：它是手动上传的，以后每次改都得重新拖一遍。适合"只演示一次"的场景。

## 四、演示：三分钟讲完

### 结构（背下来，别临场想）

```
① 痛点（15 秒）
   "以前要看这些数，得手动打开四个表格加一遍，要半小时。"

② 演示（2 分钟）—— 只讲三个数字
   "这是我们的页面。第一个数：总访问量 14,560。"
   "第二个数：转化率 3.91%——重点是这个，比上个月低了。"
   "第三个数：客单价 175,607 元。"
   "（顺手点一下筛选器）按渠道看，自然搜索占了六成。"

③ 结论（30 秒）
   "所以我们知道信息流渠道转化最差，建议先查那边。"
```

### 三个关键点

**1. 只讲三个数字，不要讲五个。**

五个数字观众一个都记不住。挑最有故事的三个，其余留在页面上让人自己看。

**2. 一定要点一次筛选器。**

这是页面上唯一的"交互"。点了，观众才相信它不只是张图片。**提前练这个动作，别现场手忙脚乱。**

**3. 结论必须是你自己的判断。**

"这就是我们的数据"——这是废话。
"所以我们应该先查信息流"——这是判断，有判断才有价值。

## 五、演示前 30 分钟检查

对着打勾，**一条都别跳过**：

- [ ] 网址能打开（用**手机流量**打开一次，不要只用自己电脑——学校网络可能屏蔽 GitHub）
- [ ] 网址存在手机备忘录里，别现场搜
- [ ] 页面数字是对的，跟你们最后核对的一致
- [ ] 按 `F12` 没有红字报错
- [ ] 筛选器点一下确实会变
- [ ] **录屏文件存在本地，能播放**（见下一条）
- [ ] 至少两个人试讲过一遍
- [ ] 讲稿打印出来了（不要照着屏幕念）

### 录屏（必备保险）

用 Windows 自带的就行：

1. 按 `Win + G` 打开游戏栏
2. 点录制按钮，或按 `Win + Alt + R` 开始/结束
3. 文件默认存在 `视频\捕获` 文件夹

**录什么：** 打开网址 → 慢慢滚一遍 → 点一下筛选器 → 停 5 秒。**不需要说话。**

现场网断了，就放这个，然后正常讲解。**没人会觉得这是作弊，这叫做准备。**

---

## 六、演示时可能出的问题

| 情况 | 怎么办 |
| --- | --- |
| 网断了 | 放录屏，继续讲 |
| 网址打不开 | 放录屏；或者本地双击 `index.html` 投屏（**提前把这 4 个文件拷到演示电脑上**） |
| 页面显示旧数据 | `Ctrl + F5` 强制刷新 |
| 老师问"这个数怎么算的" | 翻到页面底部，那儿有口径说明——**这就是为什么第 5 天必须补上它** |
| 老师问"数据哪来的" | 页面顶部有数据来源。答不上来时不要编，说"这个数据是 XX 提供的" |

## 七、演示之后

如果还要继续改这个项目：

1. 把这次演示里别人提的问题记下来
2. 别在演示当天改代码。**先歇一天，第二天再动**
3. 下次改之前，先想清楚：是加功能，还是把现有的做扎实？——**通常是后者**

## 八、一句话总结

上线就用 GitHub Pages，5 分钟的事，第 1 天就能开。
演示只讲三个数字，加一句自己的判断，再录个屏当保险。
