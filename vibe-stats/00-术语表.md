## 一、关于文件

### 文件 / 文件夹
电脑上的东西。文件夹里装文件，也可以装别的文件夹。

### 路径
文件在电脑里的"地址"。比如 `D:\项目\index.html` 意思是：D 盘 → 项目文件夹 → index.html 这个文件。

### 根目录
"最外层的那一层"，没有更外层了。

### 扩展名（后缀名）
文件最后的 `.xxx`，告诉你这是什么文件：
- `.html` = 网页结构
- `.css` = 样式
- `.js` = 程序的逻辑
- `.md` = 说明文档（你现在看的这种）
- `.json` = 一种数据格式

> 如果看不到扩展名，在文件资源管理器里打开"查看 → 显示 → 文件扩展名"。**强烈建议打开**，不然你分不清 `index.html` 和 `index.html.txt`。

## 二、关于网页

### HTML
网页的**骨架**：页面上有哪些东西、顺序是什么。
对应我们的 `index.html`。

打个比方：HTML 是一栋楼的**房间布局**——哪里是客厅、哪里是卧室。

### CSS
网页的**样子**：颜色、大小、间距、字体。
对应我们的 `style.css`。

打个比方：CSS 是**装修**——墙刷什么颜色、家具多大。

### JavaScript（简称 JS）
网页的**行为**：点按钮之后发生什么、数字怎么算、图怎么画。
对应我们的 `data.js` 和 `app.js`。

打个比方：JS 是**电和管道**——按开关灯会亮，拧龙头出水。

### 浏览器
Chrome、Edge、Firefox。它们的工作就是**读懂 HTML + CSS + JS，画成你看到的页面**。

### 刷新（F5）
改完文件后按 `F5`（或 `Ctrl + R`），让浏览器重新读一遍文件。

> 如果改了没反应，按 `Ctrl + F5`（强制刷新），因为浏览器会偷偷记住旧版本。

### 控制台（Console）
浏览器里给开发者看的"报错窗口"。
打开方法：按 `F12`，点上面的 **Console**（控制台）标签。

**这是你排查问题最重要的工具。** 页面白屏了、数字变成 `NaN` 了，这里会有红字告诉你哪里坏了。
**没有红字，说明代码没报错**，问题在别处。

### 元素 / 区块
页面上的一个"块"。比如一张卡片、一张表格、一条筛选栏。

### 容器
一个空的区块，先占好位置，以后再往里放内容。
我们 `index.html` 里那些 `<section>`、`<div>` 就是容器。

### 响应式 / 手机适配
页面在窄屏幕上也能正常看（不横向滚动、字不挤在一起）。

### 溢出
内容超出了它的框，跑到外面去了。比如一个特别长的数字把卡片撑破。

## 三、关于版本管理（最重要的一段）

这一段的词你不懂，就没法跟队友配合。**但每一个都很简单。**

### 仓库（Repository，简称 repo）
**一个项目的文件夹，附带"每一次改动的完整历史"。**

打个比方：普通文件夹是**一张当前的照片**；仓库是**一整本相册**，能看到每一版长什么样、谁改的、什么时候改的。

我们的仓库就是那 4 个文件所在的文件夹。

### GitHub
一个**放仓库的网站**。你们四个人的电脑上没有直接连线，靠 GitHub 当中转站：

```
你的电脑  →  上传到 GitHub  →  队友从 GitHub 下载到他的电脑
```

**GitHub 不是 Git。** Git 是装在你电脑上的工具，GitHub 是网站。就像 Git 是"快递打包手艺"，GitHub 是"快递公司"。

### 克隆（Clone）
**第一次**把一个仓库从 GitHub 完整下载到自己电脑。

打个比方：把整本相册复印一份带回家。**只做一次**。

### 拉取（Pull）
把**别人上传的新改动**下载到自己电脑，和你现在的文件合并。

打个比方：相册有新照片了，你去取一下最新版。

**每天开始工作前第一件事就是拉取。** 不拉就会跟别人打架。

### 提交（Commit）
把你这次的改动**记录成一个"版本"**，附上一句说明。

打个比方：给相册里这一页写上"3 月 5 日，改了首页配色"。

> 注意：提交只是记在**你自己电脑上**，还没传到网上。

### 上传 / 推送（Push）
把本地的提交**传到 GitHub**。

**提交 + 推送 = 别人才能看到你的改动。**

### 分支（Branch）
从当前版本**岔出去**一条独立的线，在上面改东西不影响主线。

打个比方：**平行时空**。你在平行时空里试一个新想法，搞砸了也不影响原来的世界；搞好了再合并回去。

> **新手建议：一开始不用分支。** 直接在主线上改就行——因为我们一人一个文件，几乎不会撞。
> 等你们熟练了、或者需要试一些危险改动时，再学分支。具体看 [`02-分工和每天配合.md`](02-分工和每天配合.md)。

### 合并（Merge）
把分支的改动合回主线。

### 冲突（Conflict）
**两个人改了同一个文件的同一行**，Git 不知道该听谁的，于是停下来问你。

页面上会出现这样的东西，你需要手动选一个：

```
<<<<<<< 你的
这里的颜色是红色
=======
这里的颜色是蓝色
>>>>>>> 队友的
```

**新手最怕这个，其实不可怕。** 处理步骤在 [`06-出问题怎么办.md`](06-出问题怎么办.md)。
最好的办法是**根本不产生冲突**——一人一个文件，就不太会冲突。

### 主分支（main）
仓库的主线，叫 `main`。别人下载到的就是这条线。

## 四、关于数据

### 数据 / 数据集
一堆记录。我们的数据是"一行 = 某一个渠道在某一天的汇总"。

### 字段（Field）
一行数据里的一个"格子"，比如 `visits`（访问量）。
可以理解成 Excel 里的一列。

### 记录（Record / Row）
一行数据。对应 Excel 里的一行。

### JSON
一种写数据的格式。长得像这样：

```json
{ "date": "2024-03-01", "visits": 1280 }
```

`{ }` 包起来的是一个对象，里面是 `字段名: 值` 一对一对的。

**你不需要手写 JSON。** 我们把它写在 `data.js` 里，用的是几乎一样的写法，但可以加注释（纯 JSON 不能写注释）。

### 假数据 / Mock 数据
**在真实数据还没到位时，先手写几行"像真的"的数据**，让页面先能开发。

新手常常随便写 `{value: 1}` 敷衍过去，结果真实数据一进来就崩。所以我们提供的假数据是**故意做脏的**（见下一条）。

### 脏数据
真实数据里那些"不干净"的情况。我们强制要求假数据里包含这五种：

| 脏在哪 | 例子 | 不处理会怎样 |
| --- | --- | --- |
| 空的 | 一条记录都没有 | 页面空白或报错 |
| 缺字段 | 没有渠道、没有金额 | 显示 `undefined` |
| 数字写成了文字 | `"980"` 而不是 `980` | 算出来变成字符串拼接 |
| 特别大的数 | `99999999` | 撑破卡片布局 |
| 格式不统一 | `2024-3-5` 和 `2024/03/09` | 排序、筛选全乱 |

### 数据契约
**四个人先说好：一行数据长什么样、每个字段叫什么名字、什么类型。**

打个比方：**先定好表格的列名，再各自填表**。如果不定，A 写 `visits`、B 写 `visitCount`、C 写 `访问量`，合起来就全对不上。

我们的"契约"就是 `data.js` 最上面那个 `window.DATA` 的形状。**这个形状定下来之后，不要随便改**，要改先跟全组说。

### 指标
页面上显示的一个数字，比如"总访问量"。

### 口径
**这个指标是怎么算出来的。** 这是统计页面最重要的东西。

比如"转化率"的口径是「订单数 ÷ 访问量」。如果不说清楚，别人看到 3.91% 也不知道你算什么。

**页面上必须能看到口径**——我们放在每张卡片标题后面的小问号里，还有页脚。

### 纯函数
一种函数：给同样的输入，永远得到同样的输出，中间不偷偷改别的东西、不联网、不弹窗。

好处：能单独拿出来测试，出错了很好查。
我们的计算函数（`data.js` 里的）都是纯函数，页面上的显示逻辑都不在里面。

## 五、关于让 AI 帮忙

### 提示词（Prompt）
你发给 AI 的那段话。

### 上下文
AI 在当前这次对话里"记得"的东西。

> AI **看不到你的项目文件夹**。你不告诉它，它就不知道你们叫什么字段、文件在哪。
> 所以提问时必须**直接给它文件路径、把相关代码贴给它**。

### 幻觉 / 瞎编
AI 自信地给你一段**根本不存在**的东西——比如一个不存在的函数名、一个你们没用过的库。

**这是我们这个项目最常见的坑。** 防范方法在 [`04-怎么问AI.md`](04-怎么问AI.md)。

### 依赖 / 库 / 类库
别人写好的、可以直接用的代码包。

**我们这个项目故意不用任何依赖**——不用 npm、不装包。
理由：少一个依赖就少一个装不上、版本冲突、报错的来源。对新手，纯 HTML/CSS/JS 最稳。

> 如果 AI 让你 `npm install` 什么东西，**先别照做**，看 [`04-怎么问AI.md`](04-怎么问AI.md)。

## 六、关于上线

### 部署（Deploy）
把本地的网页**放到一台全天开着的服务器上**，让任何人都能通过网址访问。

### 网址 / 域名
`https://xxx.github.io/项目名/` 这样的一串。别人打开它就看到你们的页面。

### GitHub Pages
GitHub 免费提供的"托管网页"功能。**我们的第一选择**，因为它跟仓库连在一起，上传代码就自动更新网站。

步骤见 [`05-上线和演示.md`](05-上线和演示.md)。

### 缓存
浏览器为了变快，会**偷偷存一份旧版本**。所以有时你更新了，别人看到的还是旧的。

解决办法：让对方按 `Ctrl + F5` 强制刷新。

---

## 七、一句话总结

如果你只记三件事，记这三件：

1. **仓库 = 带历史的文件夹**；提交 = 记一个版本；上传 = 传到 GitHub 让队友能拿到。
2. **一人一个文件**，是你们不打架的唯一法宝。
3. **口径**必须写在页面上，不然数字没有意义。
